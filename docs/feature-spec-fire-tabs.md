# 퇴사나이 FIRE 탭 구조 기능명세서

## 1. 프로젝트 목표

퇴사나이 앱을 단순 은퇴 계산기에서 한국형 FIRE 시뮬레이터로 확장한다.

핵심 목표는 다음과 같다.

1. 사용자가 모바일에서 빠르게 입력하고 결과를 확인할 수 있게 한다.
2. 계산기 화면이 길어지지 않도록 탭 구조로 정리한다.
3. 고급 기능은 기본 화면을 방해하지 않도록 접힘/옵션형으로 제공한다.
4. 개인정보 수집 없이 브라우저 내 계산 중심으로 운영한다.
5. 구글 애드센스 승인에 불리하지 않도록 정책, 면책, 콘텐츠 구조를 명확히 한다.
6. 향후 환율 API, 해외 체류, 건강보험료, 커뮤니티 연결을 유지보수 가능한 구조로 확장한다.

## 2. 설계 원칙

### 2.1 UX 원칙

- 탭은 최대 3개로 유지한다.
- 기본 사용자는 계산기 탭만으로 결과를 볼 수 있어야 한다.
- 고급 설정은 기본 접힘 상태로 둔다.
- 결과 확인을 위해 별도 결과 탭 이동을 강제하지 않는다.
- 모바일 기준으로 먼저 설계한다.
- 계산 버튼, 결과 카드, 공유 버튼은 항상 명확해야 한다.

### 2.2 보안/개인정보 원칙

- 이름, 이메일, 주민번호, 주소, 계좌, 카드, 로그인 정보를 수집하지 않는다.
- 사용자의 입력값은 기본적으로 브라우저 localStorage에만 저장한다.
- 서버로 자산 입력값을 전송하지 않는다.
- API Key는 프론트엔드 번들에 포함하지 않는다.
- 환율 API는 추후 Cloudflare Worker 같은 서버리스 함수에서 호출한다.
- 공유 이미지에는 이름, 이메일, IP, 식별값을 포함하지 않는다.

### 2.3 애드센스/정책 원칙

- 푸터에 개인정보처리방침, 이용약관, 면책고지, 문의 링크를 유지한다.
- 서비스는 투자 권유, 금융상품 추천, 세무/법률/재무 자문이 아니라는 점을 명확히 한다.
- 건강보험료, 세금, 비자, 환율 관련 문구는 확정 표현이 아니라 추정/참고/확인 필요 표현을 사용한다.
- 광고 영역은 입력폼과 계산 버튼 사이에 넣지 않는다.
- 광고가 결과보다 먼저 보이지 않도록 한다.
- 자체 커뮤니티 기능은 애드센스 승인 전에는 만들지 않는다. 우선 외부 링크 또는 피드백 채널로 연결한다.

## 3. 최종 정보구조 IA

상단 메인 탭은 다음 3개로 구성한다.

1. 계산기
2. 분석
3. 공유

### 3.1 계산기 탭

목적: 사용자가 핵심값을 입력하고 즉시 결과를 확인하는 메인 화면.

구성:

1. 기본 입력 카드
2. 고급 설정 접힘 카드
3. 결과 요약 카드
4. 참고용 시뮬레이션 고지
5. 개인정보 보호 고지

### 3.2 분석 탭

목적: 입력 결과를 바탕으로 민감도와 고급 시나리오를 보여주는 화면.

구성:

1. 수익률별 결과
2. 생활비별 결과
3. 해외 체류 효과
4. 건강보험료 영향
5. 환율 민감도
6. 연도별 상세표

### 3.3 공유 탭

목적: 계산 결과를 저장, 복사, 공유하고 커뮤니티/피드백으로 연결하는 화면.

구성:

1. 결과 요약 복사
2. 계산 링크 복사
3. 결과 이미지 저장
4. 커뮤니티/피드백 연결
5. 공유 전 개인정보 주의 문구

## 4. 화면별 기능명세

## 4.1 계산기 탭

### 4.1.1 기본 입력 카드

컴포넌트명 후보:

- `CalculatorTab`
- `InputForm`
- `BasicInputSection`

입력 항목:

| 필드명 | 키 | 단위 | 기본값 예시 | 필수 여부 |
|---|---|---:|---:|---|
| 현재 나이 | currentAge | 세 | 34 | 필수 |
| 목표 퇴사 나이 | targetRetirementAge | 세 | 39 | 필수 |
| 현재 투자자산 | currentAssets | 만원 | 23000 | 필수 |
| 월 추가 투자금 | monthlyInvestment | 만원 | 100 | 필수 |
| 퇴사 후 월 생활비 | monthlyLivingCost | 만원 | 500 | 필수 |
| 기대 연수익률 | annualReturnRate | % | 7 | 필수 |
| 물가상승률 | inflationRate | % | 2.5 | 필수 |

주요 정책:

- 숫자 입력만 허용한다.
- 단위는 입력창 오른쪽에 표시한다.
- 입력값 변경 시 자동으로 시뮬레이션을 갱신한다.
- 계산 버튼은 명시적으로 제공하되, 실제 계산은 상태 변경 기반으로 즉시 반영 가능하다.

문구:

> 현재 자산, 월 투자금, 퇴사 후 생활비를 입력하면 목표 나이에 퇴사했을 때 자산이 몇 살까지 버티는지 계산합니다.

### 4.1.2 고급 설정 카드

기본 상태: 닫힘

버튼 문구:

> 고급 설정 펼치기
> 국민연금 · 추가소득 · 건보료 · 해외체류 · 환율

포함 섹션:

1. 국민연금
2. 퇴사 후 추가소득
3. 건강보험료 추정
4. 해외 체류 시나리오
5. 환율 설정

### 4.1.3 국민연금 섹션

입력 항목:

| 필드명 | 키 | 단위 | 기본값 예시 |
|---|---|---:|---:|
| 국민연금 반영 여부 | pensionEnabled | ON/OFF | ON |
| 국민연금 수령 시작 나이 | pensionStartAge | 세 | 65 |
| 예상 월 수령액 | monthlyPension | 만원 | 100 |

문구:

> 국민연금은 실제 수령액과 수령 시점에 따라 결과가 크게 달라질 수 있습니다.

### 4.1.4 퇴사 후 추가소득 섹션

입력 항목:

| 필드명 | 키 | 단위 | 기본값 예시 |
|---|---|---:|---:|
| 추가소득 반영 여부 | sideIncomeEnabled | ON/OFF | OFF |
| 퇴사 후 월 추가소득 | monthlySideIncome | 만원 | 100 |
| 추가소득 시작 나이 | sideIncomeStartAge | 세 | 40 |
| 추가소득 종료 나이 | sideIncomeEndAge | 세 | 55 |

문구:

> 파트타임, 프리랜서, 임대소득 등 퇴사 후 발생할 수 있는 소득을 반영합니다.

### 4.1.5 건강보험료 추정 섹션

1차 버전에서는 API 연동을 하지 않는다. 사용자가 예상 월 건강보험료를 직접 입력한다.

입력 항목:

| 필드명 | 키 | 단위 | 기본값 예시 |
|---|---|---:|---:|
| 건보료 반영 여부 | healthInsuranceEnabled | ON/OFF | OFF |
| 예상 월 건강보험료 | monthlyHealthInsurance | 만원 | 25 |
| 장기요양보험 포함 여부 | longTermCareIncluded | ON/OFF | ON |
| 해외 장기체류 반영 여부 | overseasInsurancePauseEnabled | ON/OFF | OFF |

필수 안내 문구:

> 건강보험료는 소득, 재산, 세대 구성, 피부양자 여부에 따라 달라집니다. 실제 부과액은 국민건강보험공단 기준을 확인해야 합니다.

해외 체류 문구:

> 3개월 이상 국외 체류 시 건강보험료 산정에서 제외되거나 급여정지·보험료 면제 대상이 될 수 있습니다. 다만 실제 적용은 가입 유형, 체류 기간, 출입국 기록, 공단 기준에 따라 달라질 수 있습니다.

금지 문구:

- 치앙마이 3개월 살면 건보료가 면제됩니다.
- 해외에 나가면 건보료를 피할 수 있습니다.
- 건보료 0원 보장.

### 4.1.6 해외 체류 시나리오 섹션

입력 항목:

| 필드명 | 키 | 단위 | 기본값 예시 |
|---|---|---:|---:|
| 해외 체류 적용 여부 | overseasStayEnabled | ON/OFF | OFF |
| 국가/도시 | overseasCity | 선택 | 치앙마이 |
| 연간 체류 개월 | overseasMonthsPerYear | 개월 | 3 |
| 1회 연속 체류일 | overseasContinuousDays | 일 | 90 |
| 현지 월 생활비 | overseasMonthlyCostLocal | 현지화 | 50000 |
| 항공권/보험/비자 등 연간 부대비 | overseasAnnualExtraCost | 만원 | 150 |
| 적용 기간 | overseasApplyYears | 년 | 10 |

도시 기본 후보:

- 치앙마이
- 방콕
- 다낭
- 발리
- 직접 입력

계산 방식:

```text
현지 월 생활비 원화 환산 = 현지 월 생활비 × 환율
월 절감액 = 한국 월 생활비 - 현지 월 생활비 원화 환산
연간 절감액 = 월 절감액 × 해외 체류 개월 - 연간 부대비
```

안내 문구:

> 해외 체류는 비자, 항공권, 보험, 환율, 숙소비, 의료비에 따라 실제 비용이 달라질 수 있습니다.

### 4.1.7 환율 설정 섹션

1차 버전은 수동 입력으로 구현한다. API 연동은 3차 버전에서 진행한다.

입력 항목:

| 필드명 | 키 | 단위 | 기본값 예시 |
|---|---|---:|---:|
| 통화 | currency | 선택 | THB |
| 환율 | exchangeRate | 원 | 40 |
| 환율 자동 업데이트 | exchangeAutoUpdate | ON/OFF | OFF |
| 환율 기준일 | exchangeRateDate | 날짜 | 수동입력 |

안내 문구:

> 환율은 참고값이며 실제 카드 결제, 환전 수수료, 송금 수수료와 다를 수 있습니다.

## 4.2 결과 요약 카드

컴포넌트명 후보:

- `ResultSummaryCard`
- 기존 `DecisionDashboard` 확장 가능

표시 항목:

| 항목 | 설명 |
|---|---|
| 메인 결과 | 목표 퇴사 나이 기준 자산 유지 가능 나이 |
| 퇴사 시 예상 자산 | 목표 퇴사 시점의 예상 자산 |
| 자산 소진 예상 나이 | 자산이 0 이하가 되는 나이 |
| 은퇴 후 첫해 생활비 | 물가 반영 후 첫해 생활비 |
| 건보료 영향 | 건보료 반영 전후 차이 |
| 해외 체류 영향 | 해외 체류 반영 전후 차이 |

메인 결과 예시:

> 39세 퇴사 시 82세까지 자산 유지 가능

위험 결과 예시:

> 39세 퇴사 시 71세에 자산 소진 예상

경고 문구 조건:

1. 자산 소진 나이가 80세 미만이면 위험 경고
2. 자산 소진 나이가 90세 이상이면 안정 문구
3. 수익률이 10% 이상이면 낙관 가정 주의 문구
4. 월 생활비가 지나치게 높으면 생활비 민감도 확인 유도

## 5. 개발 단계

## 5.1 1차 배포: 구조 정리

목표: 현재 기능을 유지하면서 탭 구조로 재배치한다.

작업 목록:

1. `App.jsx`에 `activeTab` 상태 추가
2. 상단 탭 내비게이션 추가
3. 계산기 탭에 `InputForm`, `DecisionDashboard`, `GrowthPanel`, `SummaryCards` 배치
4. 분석 탭에 `InsightReport`, `ScenarioComparison`, `YearlyTable` 배치
5. 공유 탭에 링크 복사, 결과 요약 복사, 개인정보 주의 문구 배치
6. 기존 legal/disclaimer 섹션은 하단 공통 영역으로 유지
7. 모바일 하단 바는 계산기/공유 기능과 충돌하지 않게 정리

완료 조건:

- 기존 계산 결과가 바뀌지 않는다.
- 기존 입력값 저장/localStorage가 유지된다.
- 기존 공유 링크 기능이 유지된다.
- 모바일에서 한 화면이 과도하게 길어 보이지 않는다.

## 5.2 2차 배포: 고급 입력 정리

작업 목록:

1. 고급 설정 접힘 영역 추가
2. 건보료 직접 입력 필드 추가
3. 해외 체류 수동 입력 필드 추가
4. 환율 수동 입력 필드 추가

완료 조건:

- 건보료 입력값이 자산수명에 반영된다.
- 해외 체류 입력값이 생활비 절감으로 반영된다.
- 환율 입력값이 현지 생활비 환산에 반영된다.
- 확정적/위험한 문구가 없다.

- API Key가 프론트에 노출되지 않는다.
- API 실패 시 마지막 환율 또는 수동 환율로 fallback 된다.
- 환율 기준일이 화면에 표시된다.
