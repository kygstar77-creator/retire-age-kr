# 파이어맵 2.0 리파인 백로그

자동 모바일 QA가 통과한 뒤, 스크린샷 기준으로 PM/디자인/카피 관점에서 남은 개선 항목입니다. 이 문서는 기능 추가가 아니라 사용자 경험을 앱답게 다듬기 위한 작업 목록입니다.

## 현재 상태

- Build Check: 성공
- FireMap Mobile QA: 성공
- 프리뷰 브랜치: firemap-v2-preview
- 검수용 PR: #2
- main 병합: 아직 금지

## 리파인 원칙

- 기능이 작동하는 것과 사용자가 쓰고 싶어지는 것은 다릅니다.
- 계산기는 엔지니어가 만들 수 있지만, 사용자가 공유하는 앱은 문구와 감정 UX가 결정합니다.
- 한 번에 크게 갈아엎지 않고, 작은 단위로 수정한 뒤 자동 QA와 스크린샷 검수를 반복합니다.

## 우선순위 1: 카피 리파인

### 홈

현재:

- 내 돈으로 몇 살까지 버틸 수 있을까?

개선 후보:

- 내 돈은 몇 살까지 버틸까?

목표:

- 모바일 줄바꿈을 줄이고 첫 화면의 힘을 키웁니다.

### 결과 점수

현재:

- 자산수명 점수 12/100

문제:

- 벌점처럼 보여 사용자가 낙담할 수 있습니다.

개선 후보:

- FIRE 진단: 개선 여지 큼
- 보조로 12/100 표시

목표:

- 사용자가 “망했다”가 아니라 “바꾸면 좋아진다”고 느끼게 합니다.

### 공유

현재:

- 결과카드 이미지 또는 링크 공유
- 이미지 카드 만들기/공유

개선 후보:

- 내 FIRE 결과 공유하기
- 결과 이미지 공유하기

목표:

- 설명서 같은 표현을 줄이고 행동 중심으로 바꿉니다.

## 우선순위 2: 그래프 해석성

현재 문제:

- 회색선과 주황선 의미가 약합니다.
- “다음 단계에서 점을 눌러...”는 개발자 설명처럼 보입니다.

개선 후보:

- 범례: 현재 계획 / 생활비 절감안
- 해석 문구: 현재 계획은 45세, 생활비 절감안은 49세까지 버티는 시나리오예요.

목표:

- 그래프를 장식이 아니라 의사결정 도구로 만듭니다.

## 우선순위 3: 도시 시나리오 신뢰도

현재:

- 월 330만
- 190만 절감

개선 후보:

- 예상 월 330만
- 현재 대비 190만 절감

고지 문구:

- 도시별 금액은 1인 생활비 참고 시나리오이며 실제 주거비, 의료비, 환율, 비자 조건에 따라 달라질 수 있어요.

목표:

- 숫자가 단정적인 하드코딩처럼 보이지 않게 합니다.

## 우선순위 4: 상단 버튼 정리

현재 문제:

- 일부 서브 화면에서 공유 / 결과로 / 초기화처럼 버튼이 많아 보입니다.

방향:

- 서브 화면에서는 초기화를 숨기고 결과로 돌아가는 길을 우선합니다.
- 초기화는 홈/질문/결과에서만 유지합니다.

## 우선순위 5: 하단 safe-area

현재 문제:

- 카카오톡/인앱 브라우저 하단 UI에 카드가 가려질 수 있습니다.

방향:

- 결과/서브 화면 하단 여백을 충분히 둡니다.

## 진행 방식

1. 작은 단위로 코드 수정
2. Build Check 확인
3. FireMap Mobile QA 확인
4. 스크린샷 artifact 확인
5. PM/디자인/카피 검수
6. 다음 리파인 진행

## 완료 기준

- 첫 화면이 30초 안에 이해됩니다.
- 결과 화면이 낙담보다 행동을 유도합니다.
- 그래프가 해석 가능합니다.
- 공유 화면이 설명서가 아니라 앱처럼 보입니다.
- 도시 시나리오가 placeholder처럼 보이지 않습니다.
- 자동 QA가 계속 통과합니다.
