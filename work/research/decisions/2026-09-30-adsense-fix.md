# 결정안: 애드센스 '가치가 별로 없는 콘텐츠' 판정 고치기 (2026-09-30, 순돌이)

## 상황(실측)
- firemap.kr = 파이어(조기은퇴) 가능 나이 계산기 웹앱(React SPA, Cloudflare). 하루 사용자 15~35명.
- 애드센스 pub-3225798545626010: '가치가 별로 없는 콘텐츠' 판정, '검토 요청' 버튼 있음. ads.txt·광고 코드는 이미 붙어 있음.
- 구글이 JS 실행 전 받는 HTML의 글자 수(태그·스크립트 제외):
  - 첫 화면 / : 34자(제목뿐). noscript 0, JSON-LD 1.
  - 계산기 화면(/dividend, /cities, /experiment): 140~175자.
  - 해외 도시 페이지 /fire-city/* 47개: 약 760자.
  - sitemap 561개 중 /guide/* 500개: 직접 쓴 글 100개(약 1,900자, 법 조문·절차 설명) + 숫자만 바꾼 틀 페이지 400개(plan 141, region-plan 145, regions 114, 각 약 1,000자, 문장 틀 동일).
- 비교: 같은 사장님의 다른 사이트(스티커 복사 웹앱, 애드센스 승인·월 수익 큼) 첫 화면 HTML = 6,413자(앱 안 사용법·안내 문구가 HTML에 미리 들어 있음) + noscript 사이트 소개 약 800자 + sr-only(스크린리더용) 사용법 1문단 + JSON-LD + 별도 가이드 페이지 여러 개(sitemap 등록).

## 결정안
1. 첫 화면과 계산기 페이지마다 HTML에 미리 들어가는 설명을 넣는다: 이 계산기가 무엇을 계산하는지, 입력값, 계산식(4% 규칙·복리·국민연금 반영), 출처(통계청·국민연금공단 등), 자주 묻는 질문. 사용자 화면에는 (a) noscript + (b) 계산기 아래 기본 접힘 '계산 방법' 영역으로 넣는다(사용자가 눌러 펼칠 수 있음). 화면 밖으로 밀기·투명·글자 0은 쓰지 않는다. 내용은 실제 기능과 일치.
2. 숫자만 바꾼 틀 페이지 400개: noindex + sitemap에서 제외(페이지 자체는 유지, 내부 링크 유지).
3. 직접 쓴 글 100개와 도시 47개를 sitemap 중심으로 남기고, 계산기↔관련 글 링크를 늘린다.
4. 배포 후 구글이 다시 읽은 것(Search Console URL 검사 또는 캐시 확인)을 본 뒤 사장님께 '검토 요청' 누르시라고 보고.

## 목표·제약

- 애드센스 계정은 나중에 유튜브 수익도 받는 계정 → 계정 정지 위험은 절대 피한다.

## 참모 의견 반영 후 최종 (2026-09-30 08:30)
- 전략 참모(고쳐서): 본질은 유입, noscript는 구식 잔기술 → 미리 그린 HTML(SSG/프리렌더)로. 틀 페이지 400개 정리는 찬성. 제휴(쿠팡)를 병행.
- 법 참모: noindex 적절. 봇과 사용자가 보는 글이 달라지면 안 됨. 면책 문구·제휴 표기(표시광고법) 필수. 유사투자자문으로 비치지 않게 종목·상품 권유 금지.
- 바꾼 점: ① noscript로 설명을 넣는 방식은 뺀다 → 계산기 아래 '계산 방법·자주 묻는 질문' 접힘 영역을 **빌드 때 HTML로 미리 그려** 봇과 사용자가 같은 글을 받게 한다(스꾸가 앱 안 문구를 HTML에 미리 담은 것과 같은 방식). ② 틀 페이지 400개 noindex + sitemap 제외(합의). ③ 면책·"입력값은 서버에 저장 안 함"(사실 확인 후) 문구를 계산기 옆에 짧게. ④ 쿠팡 파트너스는 가입 진행 중, 링크마다 법정 문구. ⑤ '트래픽이 적으면 승인 안 됨'은 참모 주장이며 구글 공식 기준은 확인 안 함 → 확인한다.
- 실패 신호: 검토 요청 후 같은 사유 재거절. 그때는 유입(R7)을 먼저 올리고 다시.
