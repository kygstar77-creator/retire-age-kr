# 받아쓰기 모델 비교 — readback 숫자 대조 (ai-lab, 2026-10-01 10:03)

## 과제
E-1 목소리 중 숫자가 든 문장 30개를 공개 전 readback 방식으로 받아쓰고, 대본과 맞춰 본다.
- 기존: gemini-3.5-flash-lite + readback 지시문(숫자는 아라비아 숫자로)
- 후보: gemini-3.5-transcribe(받아쓰기 전용, 8/26 공개 미리보기). 지시문 없이 오디오만 넣고, 결과는 `parts[0].audioTranscription.text`로 나옴
- 스크립트: bench/transcribe_bench.py · 원자료: bench/transcribe_E-1_lite+transcribe.json

## 결과(실측)
| | flash-lite(기존) | transcribe(후보) |
|---|---|---|
| 성공 | 30/30 | **9/30**. 나머지 21개는 HTTP 429(무료 한도), 21초 간격으로 보냈는데도 걸림 |
| 둘 다 성공한 9문장의 글자 오류율(CER) | 1.88% | **0.83%** |
| 숫자 놓침(=readback 거짓 경보) | 1회차 3문장, 2회차 1문장. 같은 음성인데 회차마다 다름 | 9문장 중 0 |
| 걸린 시간(문장당) | 2.0~5.3초 | 1.3초 |
| 비용 | 무료 | 무료 등급 있음(공식 가격표). 유료면 분당 약 $0.007 |

## 눈에 띈 것
- **lite는 회차마다 결과가 흔들린다.** 1회차에는 "490억"을 495억으로, "2분기"를 "이번 분기"로 들었고, 2회차에는 둘 다 맞게 들었다. PD 교본 07:2x에 적힌 "lite가 490억→495억"도 같은 흔들림이다.
- transcribe는 고유명사·말 그대로 받아쓰기가 낫다. "DX 부문이 사 온"을 transcribe는 맞게 들었고 lite는 "DRAM 모니터용"으로 들었다. 대신 "마이크론"을 "마이크로"로 한 번 틀렸다.
- transcribe는 숫자를 들리는 대로 쓴다("여덟 분기"). readback의 숫자 비교 함수 num()은 아라비아 숫자만 세므로, 이 모델을 쓰면 한글 숫자도 바꿔 주는 정규화가 필요하다.
- **readback 정규화의 거짓 경보(모델 탓 아님):** 대본 "8만 4,200원 / 27만 5천원"과 들은 결과 "84,200원 / 275,000원"이 숫자 틀림으로 잡힌다. num()이 '천'만 처리하고 '만'은 처리하지 않기 때문이다.

## 판정
- transcribe가 정확도는 이긴다. 하지만 **무료 한도가 너무 작아서 85문장 전량의 1차 모델로는 못 쓴다.** 9/30 성공이 실측이고, 정확한 한도 숫자는 확인 안 함.
- 도입 방식: lite가 '숫자 틀림'을 낸 문장(편당 1~3개)에만 **transcribe를 판정용 한 표로 추가**한다. 지금 쓰는 표 2개(3.1-flash-lite, flash-lite-latest)는 같은 lite 계열이라 같이 흔들린다.
- 같이 고칠 것: num()에 '만' 정규화를 넣는다(8만 4,200 → 84200).
- 유료 결재는 올리지 않는다. 판정용 몇 번이면 무료로 충분하다.
