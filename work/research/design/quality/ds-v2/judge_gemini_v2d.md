1. **입력 필드의 낮은 가독성과 정보 밀도:** 입력창이 웹 페이지의 기본 스타일(브라우저 기본 폼 느낌)에 머물러 있습니다. 토스나 뱅크샐러드는 입력 필드를 단순한 박스가 아닌, 클릭 시 몰입감을 주는 인터랙티브한 영역으로 처리하는데, 현재는 텍스트와 보더가 너무 평범하여 '입력 중'이라는 피드백이 약합니다.
2. **정보 계층의 혼란:** 결과값이 담긴 검은색 카드(상단)와 입력 폼(하단) 사이의 시각적 분리가 너무 강합니다. 결과값이 나오면 사용자는 '입력'을 멈추는데, 아래에 입력 필드가 그대로 노출되어 화면의 목적이 '계산'인지 '입력'인지 분산됩니다.
3. **불필요한 텍스트 노출:** '4,000만 원', '20만 원'과 같이 입력창 하단에 미리 보기 텍스트가 작게 노출되는데, 이는 정보의 노이즈를 만듭니다. 이미 입력창 안에 숫자가 명확히 보임에도 하단에 반복되는 텍스트는 모바일 화면의 귀중한 공간을 낭비하고 화면을 복잡하게 만듭니다.

2. **입력 필드의 '모바일 전용 UI' 최적화:** 현재의 얇은 보더 라인 입력창을 버리고, 뱅크샐러드처럼 부드러운 배경색(혹은 약간의 그레이톤)이 들어간 둥근 모서리의 입력 필드로 변경하세요. '원' 단위 텍스트를 입력창 내부로 배치하거나, 오른쪽 끝에 붙여 텍스트와의 여백을 확보해 폰트 크기를 지금보다 1.5배 키우세요.
3. **'바꾸기' 버튼의 버튼화 (CTA 강화):** 하단 '부양가족 1명·자녀 0명 — 바꾸기 >' 텍스트는 너무 작고 숨어있습니다. 이것은 사용자의 계산 결과를 바꾸는 핵심 설정값입니다. 이를 작은 버튼 형태로 묶거나, 칩(Chip) 컴포넌트로 만들어 인터랙티브하게 터치하고 싶게끔 명확한 경계를 만드세요. 

**한 줄 평:** 지금은 '정보를 나열하는 페이지'입니다. 토스 수준이 되려면 '데이터를 시각적으로 경험하게 하는 컴포넌트'로 구성해야 합니다.

1.  **정보의 위계와 시각적 강조 부족:** 가장 중요한 결과값인 '3,621,410원'과 보조 정보(연봉 5,078만 원 등)가 지나치게 뭉쳐 있습니다. 토스나 뱅크샐러드는 핵심 숫자를 제외한 부가 정보를 세밀한 폰트와 밝은 회색으로 처리해 가독성을 확보하는데, 현재는 모든 텍스트의 볼드와 크기가 비슷해 눈에 띄는 '한 방'이 없습니다.
2.  **테이블 디자인의 답답함:** 공제 내역을 단순 텍스트 나열형 리스트로 구성하여 매우 사무적(공공기관 웹사이트 느낌)입니다. 핀테크 앱이라면 각 항목 간의 여백을 넓히고, 배경색이나 아이콘을 활용해 금융 데이터를 '개인화된 정보'로 보이게 해야 하는데, 현재는 데이터 시트 그 자체입니다.
3.  **CTA(행동 유도) 버튼의 이질감:** 하단의 '퇴직금도 계산하기' 버튼이 화면 좌우 끝까지 꽉 차 있고, 색상도 지나치게 채도가 높은 파란색입니다. 토스식의 부드러운 라운드 처리나 주변 배경과 어우러지는 톤앤매너가 부족하여, 마치 웹 페이지의 클릭 버튼을 억지로 모바일에 맞춘 듯한 투박함이 느껴집니다.

### 2. 8점으로 올릴 고칠 점
1.  **핵심 정보 카드화 (Card UI):** '월 실수령액' 결과 부분을 별도의 박스(카드) 형태로 분리하세요. 배경색을 미세하게 넣거나 카드 형태로 묶고, 하단의 부가 정보(연봉, 비과세 등)는 폰트 사이즈를 확 줄여서 상단 결과값과의 시각적 체급 차이를 확실히 벌려야 합니다.
2.  **공제 내역 시각화 (인포그래픽 활용):** 공제 내역 리스트 앞에 해당 보험의 성격(예: 4대 보험/세금 등)을 구분하는 아주 작은 아이콘이나 컬러 점을 추가하세요. 또한 각 금액을 오른쪽 정렬로 깔끔하게 맞추되, 맨 마지막 '합계' 줄에는 배경색이나 강조 선을 추가해 데이터의 마침표 역할을 확실히 해야 합니다.
3.  **버튼 디자인 개선:** 버튼의 모서리 굴곡(Radius)을 더 크게 키우고(최소 12px 이상), 버튼의 가로 길이를 화면 너비에서 32px(좌우 16px) 정도 안쪽으로 들여와 '떠 있는 버튼' 느낌을 주세요. 버튼 내 텍스트는 굵게 하고, 버튼 배경색을 현재의 강한 파란색에서 좀 더 채도가 낮거나 부드러운 브랜드 컬러로 변경하면 훨씬 세련되게 보입니다.

## salary-v2
[모델 gemini-3.1-flash-lite]
모바일 UI 심사위원으로서 파이어맵(firemap.kr)의 v2 시안을 토스·뱅크샐러드 수준의 기준에서 냉정하게 평가합니다.

**점수: 6.5**
(국내 평균보다는 정돈되어 있으나, 토스의 '간결함'과 뱅크샐러드의 '금융적 신뢰감'을 주기에는 아직 디테일이 부족합니다.)

### 1. 점수를 깎은 이유 3가지
1.  **시각적 우선순위의 모호함 (Hierarchy):** 상단 결과 카드(검은색 박스)가 너무 강렬하여, 사용자가 실제로 조작해야 할 입력 폼(연봉/비과세액)과의 관계가 단절되어 보입니다. 결과값이 핵심인 것은 맞으나, 입력값이 변할 때 결과가 실시간으로 반응하는 '인터랙티브한 연결감'이 부족합니다.
2.  **불필요한 인지 부하 (Cognitive Load):** 입력란 하단에 '4,000만 원', '20만 원'과 같이 작은 글씨로 한글 표기를 병기한 것은 중복 정보입니다. 이미 숫자 필드 내에 숫자가 적혀있는데 하단에 또 표기하는 것은 토스식 UI에서는 삭제되어야 할 '노이즈'입니다.
3.  **CTA 버튼의 위치와 목적성:** '이 돈이면 몇 살에 은퇴?' 버튼이 연봉 계산기라는 기능 내에서 너무 튑니다. 사용자 입장에서 지금 필요한 것은 '계산'인데, 은퇴로의 전환(Cross-selling)을 너무 앞세워 심리적 저항감을 줍니다.

### 2. 8점으로 올리기 위한 구체적인 수정 제안 3가지
1.  **입력부와 결과부의 통합 (Input-Result Sync):** 
    *   입력 폼과 결과 박스의 거리를 줄이고, 입력 값이 변경되는 즉시 결과가 인터랙티브하게 변하는 효과를 강조하세요. 
    *   '연봉/월급' 탭을 최상단으로 올리고, 그 아래에 바로 입력창을 배치하여 '입력 -> 결과 확인'의 흐름을 토스처럼 한 화면에 일체화하십시오.
2.  **입력 폼의 금융 앱화 (Form Simplification):**
    *   하단의 작은 글씨(4,000만 원 등)를 과감히 삭제하고, 입력 필드 내에 플레이스홀더를 활용하여 깔끔하게 정리하세요. 
    *   '부양가족 1명, 자녀 0명' 정보를 수정하는 '바꾸기' 버튼을 현재처럼 우측 하단에 두지 말고, 탭 형태나 명확한 버튼 형태로 배치하여 사용자의 수정 의도를 즉각적으로 받아들여야 합니다.
3.  **CTA 버튼의 금융 맥락 재설정:**
    *   '이 돈이면 몇 살에 은퇴?'라는 버튼 대신, 계산기 하단에 **'내 자산 관리 시작하기'** 혹은 **'더 정확하게 계산하기'**와 같이 사용자가 계산 결과에 이어서 자연스럽게 다음 금융 행동을 할 수 있는, 조금 더 부드러운 유도 문구(Soft CTA)로 변경하십시오. 지금의 버튼은 너무 마케팅적입니다.

**총평:** 현재의 UI는 정보를 나열하는 데는 충실하지만, '금융 앱'이 주는 정돈된 쾌적함은 부족합니다. **'덜어내기'**와 **'연결성'**에 집중하면 8점대 진입이 충분히 가능합니다.

## stitch-claude
[모델 gemini-3.1-flash-lite]
모바일 UI 심사위원으로서 '파이어맵' 시안을 토스·뱅크샐러드와 같은 핀테크 앱 완성도 기준으로 냉정하게 평가합니다.

**점수: 5**

---

### 1) 점수를 깎은 이유 (현재 시안의 한계)
1. **시각적 위계(Visual Hierarchy)의 부재:** 가장 중요한 정보인 '월 실수령액'과 부차적인 정보인 '공제 내역'이 단순히 줄글과 표 형태로 나열되어 있어, 토스처럼 **"한눈에 핵심을 찌르는" 임팩트**가 없습니다.
2. **여백과 밀도의 불균형:** 전체적인 폰트 크기가 작고 정보 간의 간격이 일정하여, 스마트폰에서 봤을 때 '표'를 읽는 듯한 딱딱한 문서 느낌을 줍니다. 핀테크 특유의 '경험'이 아닌 '계산기 결과물' 수준에 머물러 있습니다.
3. **CTA(행동 유도 버튼)의 단조로움:** 하단 '퇴직금도 계산하기' 버튼이 주변 디자인과 너무 동떨어져 덩그러니 놓여 있습니다. 토스처럼 인터페이스의 일부로 녹아들지 못하고, 웹사이트의 기능 버튼처럼 보입니다.

---

### 2) 8점으로 올릴 고칠 점 (UX/UI 개선안)
1. **상단 결과 영역의 '카드화(Card UI)':**
   - 현재 텍스트로 나열된 ‘월 실수령액’과 ‘연봉 정보’를 별도의 배경색이 들어간 카드 박스 안에 넣으세요. 금액 폰트를 지금보다 1.5배 이상 키우고 굵게(Bold) 만들어, **사용자가 진입하자마자 0.1초 만에 확인**할 수 있게 하십시오.
2. **공제 내역의 리스트화 및 인터랙티브 요소 도입:**
   - 촘촘한 표를 버리고 토스의 '내역' 화면처럼 간격(Padding)을 넓힌 깔끔한 리스트로 바꾸세요. 공제 내역을 기본적으로는 '접기/펼치기' 상태로 두어, **핵심 정보(실수령액)에 집중하게 하고 필요한 사람만 상세 내역을 확인**하게 하는 것이 현대적인 모바일 UI입니다.
3. **CTA 버튼의 개선 (맥락적 연결):**
   - 하단 버튼을 단순한 '퇴직금 계산기'로 끝내지 마십시오. "이 연봉으로 대출 한도 조회하기" 또는 "내 노후 자금 시뮬레이션하기"처럼 **사용자의 다음 행동을 유도하는 핀테크적인 가치 전달형 버튼**으로 바꾸고, 버튼의 모서리 곡률(Corner Radius)을 지금보다 크게 조정하여 더 부드럽고 친근한 인상을 주어야 합니다.
