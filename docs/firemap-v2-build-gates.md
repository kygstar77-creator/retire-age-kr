# 파이어맵 2.0 개발 순서와 자정검사 게이트

파이어맵 2.0은 기능을 생각나는 대로 붙이지 않고, 아래 순서와 검수 기준을 통과한 것만 반영합니다.

## 원칙

1. 뼈대가 먼저다.
2. 한 번에 너무 많은 기능을 넣지 않는다.
3. 사용자가 직접 만지는 흐름을 먼저 완성한다.
4. 기능 추가 전 반드시 기존 합의와 충돌하는지 확인한다.
5. 코드 변경 후 문서와 FigJam 기준을 같이 업데이트한다.
6. main 운영 반영 전 preview 브랜치에서 모바일 테스트한다.
7. MVP에서 멈추지 않고, 최종 FIRE 의사결정 플랫폼으로 확장 가능한 구조를 유지한다.

## 전체 개발 순서

### 0단계. 기준 정리

완료 조건:

- `docs/firemap-v2-decisions.md`에 핵심 의사결정 기록
- FigJam에 동일한 흐름 반영
- preview 브랜치에서만 작업

자정검사:

- 브랜드, UX, 입력 단위, 문구가 기존 합의와 맞는가?
- 개발자용 메모가 사용자 화면에 노출되지 않는가?
- AdSense, 개인정보, 면책, 문의가 빠지지 않았는가?

### 1단계. 핵심 입력 플로우

범위:

- 홈
- 질문 5개
- 나이 1세 단위
- 금융자산 100만 원 단위
- 월 저축/생활비 10만 원 단위
- 금액 프리셋

자정검사:

- 한 화면에 질문 하나만 보이는가?
- 나이 프리셋은 제거됐는가?
- 숫자 중복 표시가 없는가?
- 직접 입력이 가능한가?
- 이전/다음 이동이 명확한가?

### 2단계. 결과 화면

범위:

- 결과 히어로 카드
- 자산수명 점수
- 안정적 퇴사 나이 문구
- FIRE를 앞당기는 4가지 카드
- 광고 첫 위치는 결과 이후

자정검사:

- 결과 문구가 과도하게 확정적이지 않은가?
- “퇴사 후 월 100만 원 벌면”처럼 의미가 명확한가?
- 생활비 절감 카드가 가장 먼저 보이는가?
- 광고가 질문 중간에 끼지 않는가?

### 3단계. 조건 바꿔보기

범위:

- 결과 이후 조건 조정
- 퇴사 나이 / 생활비 / 월 저축액
- 수익률 프리셋
- 결과로 돌아가기 버튼
- 브라우저 뒤로가기

자정검사:

- 사용자가 실수로 초기화되지 않는가?
- 결과로 돌아갈 수 있는가?
- 숫자를 바꾸면 결과와 그래프가 즉시 바뀌는가?
- 단위가 합의대로 유지되는가?

### 4단계. 그래프

범위:

- 현재 계획 vs 개선안
- 가로축 나이
- 세로축 자산 규모
- 마지막 자산 요약
- 차트 전체 터치/드래그 선택
- 세로 기준선과 선택 나이 자산 카드

자정검사:

- 축 없이 선만 있는 그래프가 아닌가?
- 사용자가 어느 시기에 얼마인지 대략 이해할 수 있는가?
- 점을 정확히 맞히는 방식이 아니라 차트 전체 터치로 동작하는가?
- 모바일에서 손가락 조작이 불편하지 않은가?

### 5단계. 도시 시나리오

범위:

- 국내: 전주 / 원주 / 강릉
- 해외: 치앙마이 / 다낭 / 쿠알라룸푸르
- 현재 생활비 대비 예상 절감액
- 최신 자료/출처 안내

자정검사:

- 컨텐츠가 너무 얕지 않은가?
- 도시별로 왜 의미가 있는지 한 줄 설명이 있는가?
- 실제 비용은 개인 상황에 따라 달라진다는 고지가 있는가?
- API/통계 자동화는 아직 무리해서 붙이지 않았는가?

### 6단계. 공유

범위:

- 결과 문구 복사
- 기본 링크 복사
- 내 조건 링크 복사
- 이미지 카드 만들기/공유

자정검사:

- 카톡에 문구만 붙여넣으면 디자인 카드가 안 나온다는 점을 고려했는가?
- 결과 이미지 카드 생성이 가능한가?
- iOS/Android에서 공유 실패 시 대체 경로가 있는가?
- 내 조건 링크에 입력값이 포함된다는 안내가 있는가?

### 7단계. 정책 / 운영

범위:

- 개인정보처리방침
- 이용약관
- 면책 고지
- 피드백·협업 문의
- AdSense 관련 파일 유지

자정검사:

- 문의 메일 `retireage.kr@gmail.com`이 남아 있는가?
- 입력값 서버 미전송 문구가 있는가?
- 참고용 계산 고지가 있는가?
- ads.txt와 publisher ID가 유지되는가?

### 8단계. MVP 이후 고급 실험

범위:

- 건보료 보수 시나리오
- 해외 체류 개월 시나리오
- 해외 체류와 건보료 일시정지 복합 시나리오
- 퇴사 후 월 현금흐름 시나리오
- 추후 배당소득세, 해외주식 양도세, 환율 API, 도시 생활비 API 연결을 위한 계산 입력 구조

자정검사:

- 고급 기능이 메인 질문 흐름을 길게 만들지 않는가?
- 결과 이후 실험 영역에서만 노출되는가?
- 자문처럼 보이지 않도록 참고 시나리오 문구가 있는가?
- 적용 버튼을 눌렀을 때 계산 결과가 실제로 바뀌는가?
- API 없이 고정 가정값을 쓸 때 가정값임을 표시하는가?

### 9단계. 데이터/API 고도화

범위:

- 환율 API
- 도시별 생활비 데이터 업데이트
- 건강보험료 조건 안내
- 배당소득세/해외주식 양도세 계산 모듈
- 통계 기반 비교 카드

자정검사:

- 출처가 불명확한 데이터가 자동 계산처럼 보이지 않는가?
- API 실패 시 기본값/캐시/안내가 있는가?
- 세무·법률 자문으로 오인되지 않는가?
- 사용자 개인정보가 서버로 전송되지 않는 구조인가?

### 10단계. 리텐션/수익화 기반

범위:

- 매일 업데이트되는 FIRE 정보
- 도시 큐레이션 고도화
- 결과 저장/비교
- 커뮤니티 후기
- AdSense 안정화 이후 제휴/프리미엄 검증

자정검사:

- 월 100만 원 수익화 목표와 연결되는가?
- 사용자가 다시 들어올 이유가 있는가?
- 인증/랭킹 같은 민감 기능은 정책 검토 후 후순위로 두는가?

### 11단계. main 반영 전 최종 검수

필수 확인:

- 모바일 첫 화면
- 질문 5개 완료
- 결과 보기
- 조건 바꿔보기
- 고급 실험
- 그래프
- 도시 시나리오
- 공유 이미지 카드
- 기본 링크/내 조건 링크
- 정책/문의
- 실제 URL 모바일 QA
- Cloudflare preview success

main 병합 금지 조건:

- preview에서 빈 화면 발생
- 모바일에서 주요 버튼이 가려짐
- 초기화가 실수로 바로 실행됨
- 정책/문의 누락
- 광고가 질문 중간에 노출
- 결과 공유가 오해를 부름
- 실제 URL QA 실패

## 변경할 때마다 해야 하는 보고 형식

1. 무엇을 바꿨는지
2. 왜 바꿨는지
3. 기존 합의와 충돌하지 않는지
4. 다음 테스트에서 확인할 항목
5. 문서/FigJam 업데이트 필요 여부
