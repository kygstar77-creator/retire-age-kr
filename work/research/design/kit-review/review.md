# 신사업 빌더 키트 — 디자인 관문 검수 (firemap-designer, 2026-10-01 08:1x)

대상: `public/kit/fmkit.js`(공유 카드 `FMKit.card`), `ventures/kit/template-ko.html`·`template-en.html`, 운영 `firemap.kr/kit/demo/`.
방법: 320·375px, 라이트·다크(prefers-color-scheme)로 Playwright 실측. 공유 카드는 운영 demo에서 `FMKit.card()`로 한국어·영어 예시 2장을 그렸다(예시 숫자는 자리표시, 계산값 아님).

## 판정: **디자인 반려** — 고칠 점 3개 (전부 몇 줄 수정, X-V1 22:00 공개 전에 끝낼 크기)

1. **큰 숫자가 넘친다.** `.result .big`이 40px·`white-space:nowrap`이라 긴 값에서 가로 스크롤이 생긴다. 실측: demo에 123,456,789,012 입력 → 320px에서 문서 폭 **346px**(넘침), 375px에서 숫자 폭 310 > 칸 303(잘림). "£6,030.17/month"나 연 단위 표시도 320px에서 위험.
   → `font-size: clamp(28px, 10vw, 40px)` + 값이 칸보다 넓으면 JS로 4px씩 줄이는 `fit`(fmkit.js 카드에 이미 있는 방식)을 화면에도. 320px 넘침 0을 launch.md에 캡처로.
2. **공유 카드 가운데 약 40%가 비어 있다**(card-ko.png·card-en.png: 숫자·설명이 위 45%에 몰리고 브랜드까지 빈 칸). 카카오톡·인스타 미리보기에서 작게 잘리면 숫자가 위로 치우쳐 보인다.
   → 제목·숫자·설명 묶음을 세로 가운데(블록 높이 계산 후 y = (S − h)/2 − 40)로, 숫자 최대 크기 150→180px. 사이트별 `accent`를 **반드시** 넘기게(기본값 파이어맵 주황 #ff5a00을 신사업 사이트가 그대로 쓰면 파이어맵 복제로 보인다 — 설계 원칙 "신사업은 분야에 맞는 별도 정체성").
3. **누르는 곳이 작다.** 머리 브랜드 링크 높이 26px, 바닥 Privacy·Contact·개인정보처리방침·문의 링크 높이 17~19px(HIG·체크리스트 44px 미만).
   → `header a, footer a { display:inline-block; padding:12px 4px; }`(글자 크기는 그대로). 링크 사이 간격 8px 이상.

## 통과한 것
- 숫자 1 + 행동 1(입력 카드 → 주황 버튼 1개 → 다크 결과 카드 1개), 글자 크기 6단(30/22/20/17/15/13), 색 토큰 소수, 다크 모드 토큰 있음, 320·375px 첫 화면 넘침 0(결과 전), 입력 48px·버튼 56px, 공유 버튼 48px(결과 뒤에만 보임 — 맞다), 면책·privacy 문구 자리.
- 공유 순서(파일 → 링크 → 복사 → 저장)와 utm 자동 붙임.

## 참고(반려 사유 아님)
- 흰 글씨/주황 #ff5a00 버튼 대비 약 3:1 — 17px 굵게는 WCAG '큰 글씨'(18.66px 굵게) 기준에 조금 못 미친다. 파이어맵 본 서비스도 같은 값이라 이번에는 두되, 신사업 사이트는 자기 accent를 정할 때 흰 글씨 4.5:1을 맞춘다(uk-pay spec 참고).
- 템플릿 FAQ의 h2 'FAQ'(20px)와 h3 질문이 거의 같은 크기로 보인다 → h3를 17px 굵게로.
